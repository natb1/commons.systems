## Answer

The conditions the record declares, gathered here and minted nowhere. This node
adds no condition of its own: each one below is cited to the node that declares
it, and a condition struck or amended there is struck or amended here.

The author's words set two. On `vocabulary-view`, 2026-09-02: the technical
vocabulary of the repository is recorded on the onboarding path of the graph and
identified in the documentation projection, and the references to tradition are
called out there too, before exit. On `attention`, and again on
`alignment-order`, 2026-09-03: the reconciliation process, shimmed as a skill, is
codified before exit.

The record's own liquidation clauses set two more. `materialization` declares
that the coverage node has ruled what the record covers, "which is a condition of
bootstrap exit and not of the swap alone". `review` declares that the batched
assessment is made, at exit, on every landing made under the reconciliation shim,
by the instrument that node describes; the instrument is not yet materialized and
a shim stands in for it, so what is owed at exit is the assessment and not the
instrument.

A shim's liquidation is not itself an exit condition, and the distinction is what
keeps the list from being circular. `work-loop`'s reconciliation shim liquidates
on clauses that include validation in use after the implementation ref is swapped
with the main branch, and `materialization` puts that swap at exit: a condition
that can only be discharged after the moment it conditions is no condition of it.
What that shim declares as an exit condition is what it names as owed before the
swap, the second direction and the drain of the legacy record, that every rule
the project runs under is a node or a declared shim, that dispatch selects from
this graph, that the alignment skill is the only path by which a node is
recorded, and that nothing live reads the legacy record; the rest of its clauses
are the shim's own liquidation and are met after exit, in use.

The swap of `greenfield` with `main` is what happens at exit and is no condition
of it, as the node above this one says. Whether the ruling of the global tier is
an exit condition is not settled by any node: the `what-acts-during-bootstrap`
node's gloss made bootstrap the state until the global tier is ruled and so
implied it, and that gloss is withdrawn on 2026-09-05; nothing else in the record
declares it, and it is not listed here. It is on the frontier as the option
`global-tier-ruled-is-a-condition`.
