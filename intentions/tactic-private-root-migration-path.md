# Document the private-root inversion — the author's private graph mounts this public graph, which keeps only intentions justifying the data structure, dispatch harness, and office-hours surface

Interview context retained verbatim for /align-tactics (2026-07-07 round that
recorded strategy-graph-mounts, privacy clarification):

- **Target state.** The author keeps a private graph of personal intentions.
  The mount relation inverts: this public graph becomes a mount ON that
  private root — the first real by-reference mount, and the reason
  mount structure must never assume same-repo residence.
- **What stays public.** Only the intentions needed to justify the
  intention-graph data structure, the dispatch harness, and the office-hours
  project. Everything person-specific (family, client/employer, personal
  duties) migrates to the private root.
- **Interim discipline this path retires.** Until the inversion lands,
  person-mounts in the public graph are role-named (never legal names),
  model duties and virtues only, and carry household consent where the
  person is identifiable (strategy-household-shared-attachments).
- **To document:** which existing nodes migrate private and which stay;
  how the by-reference mount is wired (store location, read path for the
  office-hours surface, graph-commit write path across two stores); how
  recursion and the graft relation traverse the public/private boundary;
  what the dispatch router may and may not read from the private root.
- Deliverable is the documented migration path (a design the author
  approves), not the migration itself — sequencing per the design-proposals
  rule: greenfield target plus incremental steps.
