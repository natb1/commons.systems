# Instrument: audit script that produces the strategy-recover-publishing signal reading — enumerate the published pieces on each owned publication surface and verify every piece is publicly readable with no account

## Context

`strategy-recover-publishing` has `reading: null` and its
`success_signal.sensor` is `owner review at office-hours` — the signal cannot
currently be read because nothing enumerates what has been published or checks
the machine-verifiable half of the threshold ("no piece requires a platform
account to read"). This instrument makes the owner review runnable: it audits
the two owned publication surfaces — the landing blog
(`https://commons.systems`, `landing/src/site-config.ts:6`) and fellspiral
(`https://fellspiral.commons.systems`, `fellspiral/src/site-config.ts:6`) — by
enumerating each surface's published pieces from its live RSS feed
(`<siteUrl>/feed.xml`, generated by `packages/blog/src/feed.ts:53-61` from
`packages/blog/src/feed-rss.ts`), verifying each piece is publicly readable
with no account, and emitting the platform-first attestation checklist only the
owner can complete ("no piece is platform-first" — whether any piece appeared
on a platform before the owned domain is not machine-knowable).

The instrument is **report-only**: it does not write `reading`/`gap` onto the
strategy node. The owner review at office-hours consumes the report, completes
the attestation checklist, and stamps `reading`/`gap` on
`intentions/strategy-recover-publishing.md` via `write-node.ts` +
`graph-commit` (that completion also increments the strategy's `rounds` per the
round-accounting convention in `.claude/skills/align-tactics/SKILL.md`). It is
also deliberately **not** registered in the `read-sensors.ts` default registry:
that registry is local-first no-network by design
(`packages/intentionsutil/scripts/read-sensors.ts:14-24`), and this instrument
fetches live production URLs.

The born-parked essay tactics (`tactic-blog-platform-bloat`,
`tactic-blog-enshittification-response`, `tactic-blog-maintaining-alignment`)
do not gate this instrument — the threshold quantifies over published pieces,
so the existing owned-domain output is measurable now (strategy
clarification 5).

Each unit is implemented in a subagent launched with the unit's Recommended
model, constrained to working-tree edits, and given the unit's Context/Scope
inline.

## Unit 1 — `audit-publishing.ts` script + tests

**Scope.** New script `packages/intentionsutil/scripts/audit-publishing.ts`
(tsx, no new dependencies — Node's global `fetch` suffices) plus a new test
file `packages/intentionsutil/test/audit-publishing.test.ts`.

- Resolve nothing from `cwd`; the script takes no arguments and hardcodes the
  surface list as a module const:
  `[{ name: "landing", siteUrl: "https://commons.systems" }, { name: "fellspiral", siteUrl: "https://fellspiral.commons.systems" }]`
  (values must match `landing/src/site-config.ts:6` and
  `fellspiral/src/site-config.ts:6`).
- Separate the pure core from IO so tests inject fixtures: export an async
  function (e.g. `auditSurfaces(surfaces, fetchText)`) where `fetchText:
  (url: string) => Promise<{ status: number; body: string }>` performs an
  **unauthenticated** GET (no cookies, no auth headers). The `main` entry
  wires it to global `fetch` and prints the report; guard `main` with the
  `import.meta.url === pathToFileURL(process.argv[1]).href` pattern from
  `packages/intentionsutil/scripts/read-sensors.ts:176-178`.
- Per surface: GET `${siteUrl}/feed.xml`; parse each `<item>`'s `<title>`,
  `<link>`, and `<pubDate>` (shape produced by
  `packages/blog/src/feed-rss.ts:45-70`; a simple regex/string extraction is
  fine — the feed is our own generator's output, not arbitrary XML). Unescape
  the five entities `escapeHtml` produces (`&amp; &lt; &gt; &quot; &#39;`)
  before reporting titles. A fetch failure, non-200 on `feed.xml`, or a feed
  with zero items is a **fatal error** naming the URL (clear errors over
  fallbacks, `.claude/rules/code-style.md`) — an owned surface with no
  published pieces or an unreachable feed means the instrument cannot produce
  an honest reading.
- Per piece: unauthenticated GET of the item `<link>`; the piece **passes**
  the no-account check when the response is HTTP 200 and the body contains
  the piece's title text (prerendered HTML — no JS execution, no account, no
  cookie was needed). A non-200 or missing title is a per-piece **finding**
  (reported, does not abort the run).
- Report (stdout, markdown): for each surface a table of pieces — title, URL,
  pubDate, `no-account-readable` yes/no — then a single attestation checklist
  section listing every piece as
  `- [ ] <surface>: <title> — platform-first? (owned domain first; platform posts at most syndicated copies)`
  and a trailing line telling the owner where the result lands: stamp
  `reading`/`gap` on `intentions/strategy-recover-publishing.md`. Exit `0`
  when every piece passes the machine check, `1` when any piece fails (the
  failure list is the gap evidence).
- Tests (inject `fetchText`, no network): enumeration across both surfaces
  from a hand-written two-item RSS fixture matching `feed-rss.ts`'s shape;
  entity unescaping in titles; pass/fail classification (200-with-title vs
  404 vs 200-without-title); fatal error on unreachable/empty feed; exit-code
  semantics via the returned summary object.

Out of scope: any change to `packages/blog` or the apps; registering a sensor
in `read-sensors.ts`; writing `reading`/`gap` (owner's office-hours step);
auditing platform accounts (the attestation half is human by design).

**Recommended model.** sonnet.

## Reuse

- Script-relative path + main-guard patterns:
  `packages/intentionsutil/scripts/read-sensors.ts:40-45,176-178`.
- Feed item shape (what the parser must accept):
  `packages/blog/src/feed-rss.ts:45-70`; entity set:
  `escapeHtml` in `packages/htmlutil`.
- Test conventions: sibling tests in `packages/intentionsutil/test/`
  (e.g. `sensors.test.ts`).
