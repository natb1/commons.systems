# Drift observations from the 2026-08-20 finalize of `tactic-review-fix-porcelain-guard-script`

## What this node is

An **observation carrier**. It holds the immaterial Side-B drift observations
from one `/align-tactics` tactic-mode round and **carries no implementable
scope of its own**.

**It must not be dispatched.** It is born-parked (`owner: human`,
`status: delegated`, `phase: null`, `office_hours` set) precisely so no phase
worker picks it up. There is no plan body below, and authoring one would be a
mistake — the dispositions available are decisions, not work.

Why it exists rather than the observations being written where the reference
files still say to write them: `strategy-graph-native-dispatch` clarification
**245** (violation **V1**) rules that an autonomous lane may not land dated
`clarifications` on a strategy, **overturning clarification 118**, which had
permitted exactly that from a per-node session. A tactic-target session touches
the serving strategy's frontmatter not at all. So a born-parked observation
node serving the strategy is these observations' only legal destination, and a
human promotes the worthwhile ones into `clarifications` at office hours
through the attended surface.

(`.claude/skills/align-tactics/references/write-path.md` still instructs the
caller to land `result.drift.clarifications_to_add` on the strategy. That
instruction is stale against clarification 245; the node that fixes the
Workflow and the reference file is
`tactic-align-tactics-immaterial-drift-redirect`. Until it lands, each caller
thread performs this redirect by hand, as this round did.)

## Observation 1 — clarification 244 asserts a code export that does not exist

**This is the one worth a human's eye.** The rest are recorded for provenance.

Clarification 244 defines EDIT-SUBSTANCE *negatively*, and rests the whole
definition on a named export:

> IT IS DEFINED NEGATIVELY, IN CODE, NOT BY ENUMERATION IN PROSE: schema.ts
> exports STATE_FIELDS — the router- and sensor-owned set (phase, execution,
> office_hours, reading, attention, rounds, status, blocked_by) — and
> EDIT-SUBSTANCE is EVERY field not in it.

Measured this round at `origin/main` 88ffb0c3: **`STATE_FIELDS` is not exported
from `packages/intentionsutil/src/schema.ts`, and does not appear anywhere in
code.** A repo-wide search finds the identifier only in intention prose:

- `intentions/strategy-graph-native-dispatch.md` — clarification 244 itself,
  and clarification 245's V2 disposition, which says the mechanical field check
  "is not `STATE_FIELDS.has(field)`, which is total by construction and needs
  no second list kept in sync";
- `intentions/tactic-dispatch-conflict-substance-allowlist.md` — whose Unit A
  is the node that would *create* the export;
- `intentions/tactic-finding-search-all-producers.md`.

So the sentence describes **target state in language that reads as measured
fact**, in the field that carries doctrine. That is the same decay mode
clarification 244 itself warns about two paragraphs later, when it says a prose
census "decays the day it lands" and that re-recording it as a longer prose
list does not fix it.

**Why this was immaterial to the round that found it.** The `/review-fix`
Step-5 porcelain guard checks `git status --porcelain` status codes and path
shape over newly created `intentions/<id>.md` files. It never reads the
substance/state field partition, so nothing in that node's plan depends on
whether the export exists. The finding is real but orthogonal — which is
exactly why it lands here instead of parking the work.

**Not measured:** whether any *other* consumer of the taxonomy has already been
built against the assumption that the export exists. Only the identifier's
absence was established.

## Observation 2 — scripting a prose guard fences the surface, not the invocation

Generalizable form, recorded so a later reader does not overclaim what V4's
remedy achieves.

Promoting the Step-5 checklist into a script closes the *"a prompt is not a
gate"* objection **one level, not all the way down**. After the change, the
write-surface contract is code. But the script's **invocation** by the
`/review-fix` lane is still a sentence in `SKILL.md`, so a lane that never
calls it is still unfenced by code. A guard that runs is strictly better than a
guard that is described, and the residue is smaller — but it is not zero, and
"review-fix is now mechanically fenced" would be the same shape of overclaim
that the 2026-08-14 census made and the 2026-08-15 adversarial review refuted.

**This is not an unrecorded gap and it does not widen V4's scope.**
Non-invocation of a named instrument is already governed: clarification 167
rules that a lane which cannot invoke its named instrument **fails the lane**
and parks with the rejection as its recorded reason, never substituting an
ad-hoc equivalent — carried by `tactic-lane-instrument-substitution-guard`. And
the author's V4 ruling named the remedy precisely ("promote the Step-5
porcelain checklist into a script"). No action is needed here; this is a
framing note.
