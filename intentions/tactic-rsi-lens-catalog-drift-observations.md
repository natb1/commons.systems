# Observation carrier — 2026-08-20 /align-tactics finalize of `tactic-rsi-lens-catalog-decomposition`

**This node is an observation carrier. It has no plan and must not be
dispatched.** It exists so two immaterial drift observations from an autonomous
round reach a human without an autonomous session writing onto
`strategy-recursive-self-improvement`'s `clarifications` array. Resolve it by
picking a disposition per observation (see `office_hours.recommendation`) and
then pruning it.

## Why this is a node and not a clarification

The `/align-tactics` Workflow returns immaterial Side-B premises as
`drift.clarifications_to_add`. An autonomous session must not land those on the
serving strategy:

- `clarifications` is an allowlist member of `strategyFingerprint`, so writing
  one soft-freezes **every** open child of the strategy — for an observation
  defined as gating nothing.
- It is a second requirement-entry surface, which
  `strategy-discovered-requirements` reserves to the `/align` interview.
- A model-authored dated clarification is byte-indistinguishable from an
  author-ruled one, so provenance in the field that carries doctrine collapses
  irreversibly.

The round proceeded uninterrupted; `drift.proceed` was true and no park was
written.

## Observation 1 — who actually reads a lens skill's declared `model`

Strategy clarification 46 (2026-08-14) rules that every lens becomes an
`/rsi-lens-<name>` skill "declaring its carrier field, scope tag, execution
mode and model in frontmatter."

Measured on this checkout at `origin/main` `38934c61`:

- Exactly **two** of the repo's **38** `SKILL.md` files carry a top-level
  `model:` key — `.claude/skills/commit-merge-push/SKILL.md` and
  `.claude/skills/align/SKILL.md`.
- `.claude/skills/align/SKILL.md:5-16` records (2026-07-16,
  `strategy-token-economy` clarification 10) that `model:` is confirmed
  honored only for `context: fork` skills, and that honoring is
  **unconfirmed** for `user-invocable` / main-loop skills.
- The recorded route that does work is
  `.claude/skills/implement-unit/SKILL.md:150-160` — the **outer** Agent-tool
  call sets `model` explicitly and the subagent invokes the inner skill through
  its own Skill tool.

So the declaration is real and useful, but it is applied by the **selector at
the Agent-tool launch site**, not by the harness reading the lens skill's own
frontmatter — and it is **inert** for `execution: inline` entries, which run in
the selector's own thread.

Why this is immaterial: the plan is authored to this reading already (the
selector sets `model` at the launch site), the selector-sets-model route is
recorded repo practice, and nothing in the tactic's design changes either way.

## Observation 2 — condition 14 undercounts its carrier-less lenses by one

Condition 14's 2026-08-14 amendment says "Six of the seven already comply" and
names carriers for **five**: recurring errors/`tool_errors`, variances/the
`events.jsonl` dispositions, rework/`execution.fix.attempt`,
calibration/`elapsed_s` against `window_s`, friction/`permission_friction`.

Read against `.claude/skills/rsi/SKILL.md:175-201` as checked out, lens 5
(**plan-quality yield**) also names no queryable field. It names its sources in
prose only — "units planned by `/align-tactics` against units implemented and
units reworked, plus qa findings the plan did not anticipate."

So **two** of the seven, not one, reach the catalog carrier-less.

Why this is immaterial: condition 14's own escape (name a carrier, **or** be
explicitly marked `judgment-only`) already covers it, so no author ratification
was needed to proceed. `tactic-rsi-lens-catalog-decomposition`'s plan exercises
that escape for plan-quality yield explicitly rather than letting a second lens
ship as prose.

## The generalization worth a human's eye

Both observations have the same shape: a recorded doctrine sentence that was
accurate when written, has since been outrun by the repo, and has nothing that
would catch the drift.

`tactic-rsi-lens-catalog-decomposition` is building exactly that catcher — for
lenses. Neither the `model`-honoring claim nor the six-of-seven count has an
equivalent. Three instances in one strategy on one day suggests the class is
not rare, and that is the question this node is really asking.
